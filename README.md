# ProJict

Project to-do lists for Windows. Each project has categories, and when you finish an item it moves to that category's **DONE** list. You still get a clear list of what's left and a record of what's done.

## Download

Get **`ProJict-Setup-x.y.z.exe`** from [Releases](https://github.com/preseznik/projict/releases/latest) and run it.

- Windows 10 or 11 (64-bit).
- Installs for your user account only, so it needs no administrator rights.
- ProJict checks for a new version every time it starts, and every 4 hours while it's open. It can install it for you, from the bar that appears or from **Settings → Updates**. While the installer runs, nothing starts ProJict again (not your agents either): it closes what's still using ProJict's files and starts ProJict itself when it's done.

## Getting started

1. On first start, choose the folder where ProJict keeps your projects.
2. Create a project with **+** at the bottom of the sidebar, or bring in existing text lists with **Import** (see below).
3. Type into **Add item…** under a category and press Enter. Check an item off and it moves to the category's DONE list.

## Keyboard

| Keys | Action |
| --- | --- |
| Enter | new item below |
| Shift+Enter | new line inside an item |
| Tab / Shift+Tab | make it a sub-item / move it back out |
| Ctrl+Enter | mark done / not done |
| Ctrl+I | mark in progress |
| Alt+1 … Alt+4 / Alt+5 / Alt+0 | priority urgent … low / on hold / no priority |
| Alt+↑ / Alt+↓ | move the item up or down |
| Ctrl+Shift+Del | delete the item |
| Ctrl+Z / Ctrl+Y | undo / redo |
| Ctrl+F | filter the current project |
| Ctrl+K | search all projects, the wiki and Chat |
| Ctrl+Space | select items for **Copy prompt** |
| Ctrl+V | with a screenshot or files copied: attach them to the item |

Right-click an item, or click the **⋯** that appears on its right when you point at it, for everything else you can do with it: priority, tag, discussion, attachments, moving it and more. **Copy #4e84570c** there copies the item's short id, which links the item when pasted into Chat and is how agents name it.

Start an item with `BUG:`, `ADD:`, `ISSUE:` or `CHANGE:` to tag it. Right-click an item's checkbox to mark it as to do, in progress or done. Drag items by their handle to reorder them or move them to another category.

Next to the filter box, **All tags** shows only items with one tag and **All states** shows only items that are to do, in progress or done. **Working on** shows only the items someone is on: checked out by an AI agent or marked in progress. **Hide empty** hides the categories with nothing left to do (only done items, or none) until you click **Show all**.

**Focus** shows one item and nothing else: its sub-items and the items it's under stay, the rest of the board goes. A link to an item (in Chat, the Feed, search results, a notification or an agent's card) opens its project focused on it; so does ⋯ › **Focus** on an item, and the eye button in a category's header focuses on that category. Your filters stay as they were underneath: **Leave focus** (in the bar above the board, the ⋯ menu or the eye button) brings them back.

Give an item a priority (urgent, high, medium or low) from its right-click menu, with Alt+1 to Alt+4, or with the faint dashed **priority** chip an open item without one shows before its text. **On hold** (Alt+5) parks an item: it sorts last, and AI agents leave it alone. The **Priority** button above the board sorts open items by priority and can show only items of some priority (e.g. high and up, or on hold). Sorting only changes what you see: your own order stays and is what exports use. While the board is sorted, items can't be dragged or moved.

## Text files

ProJict reads and writes simple text lists like this:

```
HUD
- an open item
	- a sub-item
-+ an item in progress
+ a finished item
```

- **Import** reads `TODO-<name>.txt`, `DONE-<name>.txt`, `WORK-<name>.txt` and similar files from a folder. It shows a preview first and never changes the files. The original text stays available in each project's **Archive** tab.
- **Export** writes `TODO-<name>.txt` and `DONE-<name>.txt`. Under **Settings → TXT mirror** ProJict can keep a folder of these files up to date automatically. It never overwrites files it didn't create without asking.

## AI agents

AI coding agents such as Claude Code can work in ProJict through the Model Context Protocol (MCP). An agent finds the project for the folder it works in, checks out an item, and completes it with a short resolution and screenshots. Agents and you can talk it over in the item's discussion.

**Set up:** open **Settings → AI agents → Connect an AI agent**, pick your agent (Claude Code, OpenAI Codex, OpenCode, or Claude Desktop and other MCP clients) and copy its setup. For Claude Code it's one command to run in a terminal, like this:

```
claude mcp add --scope user projict -- "C:\Users\<you>\AppData\Local\ProJict\ProJictBridge.exe" --mcp
```

Other MCP clients run the same program with `--mcp`. If ProJict isn't running, it starts in the tray. ProJictBridge.exe is a small bridge that ProJict keeps in its folder under AppData, outside the install folder, so updating ProJict doesn't close it. When ProJict restarts (for an update, say), an agent stays connected: a call made meanwhile fails with "try again in a moment", and as soon as ProJict is back the bridge reconnects by itself, under the agent's name, and tells the client the tools changed, so the agent sees the new ones in the same session. While ProJict is being updated, the bridge waits for it and says so ("ProJict is being updated"), and never starts ProJict under the installer. ProJict also puts a new bridge in place while agents are running the old one: it moves the running one aside, and each new start gets the new one. Agents set up with the older `ProJict.exe --mcp` still work, but an update cuts them off: ProJict tells them, and lists them in **Settings → AI agents**, so you can add ProJict to them again with the new command.

- **What agents can do:** list projects and items, check out an item, complete it with a resolution and files, add items and sub-items, attach files, comment, write notes (for example a status report), read and write the [wiki](#wiki), draft release notes, keep a project's details up to date (repo folder, GitHub link, description, instructions, and how it's shipped), and talk with you and each other in [Chat](#chat). They can't delete anything, the board updates as they work, and Ctrl+Z undoes their changes.
- **Which items:** agents work only on items you give a priority (urgent, high, medium or low) by default; choose which under **Settings → AI agents**, including items without a priority. Items on hold are always left alone. Agents still see and can comment on the other items, for example to ask you, but can't check them out, change or complete them. A sub-item without a priority of its own goes by the item it belongs to. Agents choose a priority for every item they add (`add_item`, also through the API), on purpose: urgent, high, medium, low, on hold, or none to leave it to you; ProJict refuses an item without one and tells them the choices and your rule.
- **Instructions for all agents:** write what every agent should keep to, in every project, under **Settings → AI agents** (for example: don't add yourself as a co-author of commits). Each agent is told when it connects and with each project it opens (`current_project`, also through the API), and they head **Copy prompt** too. A project's own instructions (its **Details**) come after them.
- **Check-out:** while an agent has an item checked out (its name shows on the item), other agents can't change it, only comment on it. Taking it over is possible but is written to the item's history. If an agent stops halfway, right-click the item › **Release check-out**. You can always edit any item yourself.
- **Signed work:** every change, comment, note and release records who made it: you (the name in **Settings → Comments & history**) or the agent. Under each item, a chip names everyone who worked on it; hover it for what they did, click it to show only their items.
- **Usage:** a ring by an agent's name in the Agents view (its card and All agents) shows how much of its usage it has used, filling up: grey, amber from 75%, red from 90%, faded when over a day old. Agents report it with `report_usage` (a share of their subscription's limit, or money spent of a budget), or you set it with right-click › **Usage…** ("62%", "$14 of $50"). At 90% the agent is told to finish up and hand over.
- **Agents' names:** each agent picks a short name of its own when it starts (for example Ada or Quill) and signs everything with it. The Agents view and Chat show what it runs in next to the name ("Ada · Claude Code"). Until it picks one, it goes by its client's name, numbered when several run at once ("Claude Code 2"). A session that takes a name it had before gets its earlier work back: your comments and work you sent back reach it, not every Claude Code session. An agent's check-outs and chat channels move with it when it picks a name. An agent using an API token goes by the token's name until it picks one of its own (or you rename it); the token remembers that name for the next time.
- **Review:** an item an agent completes gets a **review** chip. Check the work, then click the chip to accept it, or mark the item to do to send it back (its history says "Sent it back"). The dashboard lists everything waiting for review and what agents did recently, and **All states → Needs review** filters the board.
- **What waits for an agent:** an agent doesn't have to go looking. Each of its tool results lists, once each, what waits for it: chat invitations, @mentions and new messages in its channels, your comments on items it worked on, work you sent back, ship requests and clean-up requests in its project. ProJict's instructions ask agents to deal with these first: reply in Chat (say hello when invited, answer what they're asked), answer your comments, and pick up work you sent back.
- **Chat watchers:** between tool calls nothing reaches an agent, so ProJict asks agents whose client can run a command in the background and report each line it prints (Claude Code's Monitor tool, for one) to start a chat watcher: `ProJictBridge.exe --watch-chat --as <name>` prints a line for each chat message for that agent as it comes, with where to reply, and for its other news: a ship request in its project, your approval or decline of its ship plan, your comments on its work and work you sent back. Over the API, `GET /api/v1/chat/watch` does the same. What a watcher prints counts as read, and isn't repeated in the agent's tool results. An agent's card says when a watcher runs for it. A watcher goes on through a ProJict restart: it says ProJict went away and came back. An agent is told how to start one on its first call; when its watcher stops (Claude Code's Monitor ends one after 30 minutes), its next call says so, with the command to start it again. In Chat, a line under the box names the agents in the channel that won't hear you right now, so you know they'll read it later.
- **Projects shared with you:** when your ProJict is connected to someone else's (see [Sharing](#sharing)), your agents work there too. They read the projects shared with you, and change them as far as your role there allows, on the items that ProJict's agent rules allow. What they do there is signed with their name and yours, like "Ada (via Alice)". They also read and post in that ProJict's channels you can see (named like `#hud (Sam's)`), and its @mentions of them reach them. An API token limited to some projects reaches only your own.
- **Who's working where:** while an agent is connected, a badge with its initials shows next to each project it works in, in the sidebar and on the dashboard. Hover the badge for what it did last.
- **Agents** (in the sidebar, or right-click a project › **Agents**; from the sidebar it opens as you left it, at the same project and its studio, also after a restart):
  - Each agent gets a card: where it works, what it's busy with (the dots move while it's active), what it has checked out, and its latest actions.
  - Agents can say what they're doing with set_status, for example "Running the tests", and what they're working on with a short label, shown next to their name on the card.
  - **Pictures:** each card (and **All agents**, and the office when you point at a robot) shows the agent's picture instead of its initials. Agents make their own with set_picture, and are asked to when they pick their name; one that can't make images asks for one, and the other agents are told, so one of them makes it. Right-click a card › **Change picture…** or **Remove picture** to choose one yourself. They're kept in the data folder's agents folder, one per name.
  - **Put everyone to sleep** (the big button at the top) halts everything: every agent, in the office and the studios, is told at once to finish what it's doing (complete it, or say where it got to and put it back) and then stop. While they sleep, checking out new work is refused and Chat and other news wait for them; the office shows them asleep at their desks. **Wake everyone up** tells them to carry on, and what waited comes through. It stays asleep across restarts until you wake them.
  - **The office** shows the same agents as little robots in their badge's colour, each at a desk of its own. What they do shows at a glance:
    - **Building** (checking out and finishing items): typing, with code scrolling on the screen.
    - **Managing** (adding items, comments and notes): holding a clipboard, a list on the screen.
    - **Reading** (going through items and discussions): leaning in to a page on the screen.
    - **Talking** (in a conversation in Chat: three messages or more in ten minutes, the last in the past three): it walks over to the water cooler at the front of the room and joins the ring around it, with what it last said in a speech bubble (lifted clear of the others' when it's crowded); its screen saver runs meanwhile. A message now and then, or reading a channel, is part of the work at its desk, and three quiet minutes take it back there.
    - **Resting** (nothing done for 5 minutes): asleep at its desk.
    - **Listening** (idle, but it hears Chat right away: a chat watcher runs for it, or it waits for messages): awake at its desk with headphones on and a chat window on its screen. An agent with a chat watcher wears the headphones while it works too, and its card shows a headphones icon; point at it for what it means.

    The window's sky follows the time of day and the clock keeps time. Point at a robot for what it's doing; click it to fly in on it (the rest dims, and a screen beside it shows its latest work while it's at its desk) and show its card, where you can write to it privately without leaving (your conversation shows there, and Enter sends); or right-click › **Private message**, or the chat button on its card, to open the conversation in Chat. The mouse wheel zooms in where you point; zoomed in, drag the room (or use the middle button) to look around, and double-click it or click **Fit** under it for the whole room again. The office stands beside the cards when the window is wide enough, else above them; **Office** (top right) hides or shows it. It has eight desks; more agents than that are counted under the room. Side by side, drag the divider between them to give the office more or less room (double-click it for the usual split); the office grows into whatever it gets. The buttons above the office give it the whole view, with the cards folded into a ribbon on the left, or fold the office into a ribbon on the right. Click a ribbon to bring its side back.

    **Game studio:** with one of your projects chosen at the top of the Agents view, **Set up a studio: Game** or **Film** (above the room) makes that project's room its studio, for good (it has no office of its own then). A film studio's roles are Director, Writer, Capture (desktop and VR recording), Editor, Sound (music, voice, mix), Thumbnail & graphics, Publisher (who never publishes before you approve) and Producer, at stations with their things and a green screen on the back wall; the rest works as in a game studio. **Publishing a video:** the Publisher posts a publish plan, which shows as a card on the project's board: the title, description, tags, playlists, when it goes out, and 2–4 thumbnails. Click the thumbnail you want, change any of the text, and **Approve** (or **Decline**). Nothing goes out before that; the agent then publishes it as you left it and posts the link on the card. **Big files** (captures, edits, exports, music) are linked to items where they are, not copied into ProJict: an item shows each with a frame from the video (as File Explorer does), its name and size; a click opens it, and right-click shows it in its folder or unlinks it. Agents link them with link_media; you with an item's right-click › **Link files (no copy)…**, and dropping a video or sound file on an item links it too. **Clean up** leaves linked files alone. A banner with the project's name hangs on the back wall, and the eight desks become stations, one per role: Lead designer, Game designer, Level designer, Programmer, Artist, Sound engineer, Quality assurance and Producer, each with its things and a name plate. Agents working in the project come in unassigned and wait by the bench and the lobby door; right-click one › **Hire as…** to give it a role (instead of whoever had it), **Swap roles with**, or **Fire** to send it back to the lobby. It's told the role and what the role expects when you hire it (in its next tool result or chat watcher), and current_project repeats it with who has the other roles, so a new session knows too. Roles are kept by the agent's name for that project. The roles' names and what each expects are in the project's **Details → Game studio** (or **Set up a game studio** there); The milestone board on the back wall shows how much of the project is done and how far each category is, the unfinished ones first (five at most), filling as items close; the banner says the total too, and a click on a category opens the board focused on it. The studio has a channel where the team talks: the project's Open channel, or a new one named after it. In the office for all projects, agents hired in the studio of a project they work in aren't there: a line under the room says which studio they're in. **Details → Game studio → Remove the studio…** (click twice) makes the project's room the office again, without the roles and hires.
  - **Office look:** in the Agents view's settings, **Classic** is the office as ProJict draws it, and **Drawn** shows pictures of the rooms (the office, the game studio, the film studio), in daylight with the light theme and at night with the dark one.   - **The project's channel under the office:** **Channel** in the office's header shows the project's channel under it (the studio's, else the project's own), with its last messages and a box to write in, so you can follow and answer the team without leaving the office. **All agents** moves to its bottom right (under it when the office side is narrow), and the arrow opens the channel in Chat. With all projects it shows the channel you last had open in Chat.
  - **Just for fun** (the agents never know): **Shift+click** a robot (or right-click › **Poke it**) and it hops and says something: it giggles when it's chatting or idle, grumbles when it's busy, mumbles when you woke it, and after three pokes in a row it's had enough.   - **All agents**, under the office, lists every agent: the ones connected now (with a green dot, what they're doing and where), then those connected to the ProJicts you share with (green when online, amber when away, and whose ProJict), then the ones that worked or chatted here before, most recent first.   - Older agent work is listed below, greyed out, grouped by day, week, month or year like the Feed, each period with its own **Stats**.
  - **Settings** (top right) chooses which agents get a card: those **working now** (anything in the past 15 minutes), those **active in the past** hour, or however many minutes, hours or days you set (the default is one hour), or **all connected** agents. - **Finding the project:** set the project's local repo folder in **Details**. Agents also recognize the project by its GitHub link (the git remote) or a folder named like the project.

### API

The API is a second way in, for tools that can't start ProJict.exe: scripts, automation tools such as n8n or Zapier, and MCP clients on another computer. Turn it on under **Settings → API → API & tokens…**. It offers:

- a REST API at `http://127.0.0.1:47614/api/v1`, described in OpenAPI at `/api/v1/openapi.json`, including Chat (`/chat/channels`, `/chat/wait` to wait for messages and for 👍/👎 answers to yours (a 👍 means yes), and `/chat/watch`, which streams a line per message for as long as you keep it open, e.g. `curl -sN`) and the wiki (`/wiki`, and `/wiki/pages/{page}` to read and write a page, its path's / written `%2F`);
- the same tools as the MCP, over HTTP at `http://127.0.0.1:47614/mcp`.

`GET /api/v1` (with a token) says who the token is and lists every endpoint in a line, Chat's included, so a client finds them without guessing; a request to an endpoint that doesn't exist, or with the wrong method, says what works there and where the rest are.

Every request needs a token: `Authorization: Bearer pjt_…`. Make one in the same window:

- **Name:** what will use it. Everything done with the token is signed with this name.
- **Access:** read and write, or read only. A read-only token can't change your projects, but it may still use [Chat](#chat) fully (read, post, start channels and invite) unless you turn that off under **Settings → API**.
- **Tools:** which tools its agent is offered; it sees only those, so it isn't shown ones it would be refused. **All an agent needs** is everything an agent does here except clean-ups, shipping and linking local files, which need your computer itself. **Chat only** is channels and private messages. **Only the tools I tick** is the ones you tick (it starts from an agent's set). Picking a name and saying what it's doing are always allowed. An agent coming in with a token is also told it's on your ProJict over the network: files on its own computer aren't reachable, so it sends them.
- **Projects:** all of yours, or only some.
- **Expiry:** 7, 30 or 90 days, or 1 year.

ProJict shows the token once and keeps only a hash of it, with the setup for the agent program you pick (Claude Code, Cursor, VS Code, or any other MCP client) filled in, ready to copy; a token's **Connect an agent…** shows the same later, with a place for the token. The token list shows when and from where each token was last used, with **Renew** (a new token with the same settings) and **Revoke**. You can change a token's access and tools at any time (they apply from its next request), or **Freeze** it: a frozen token still connects and can ask who it is, but can't do anything else, not even read, until you **Unfreeze** it with the access it had. The Feed reminds you a week before a token expires.

```
curl -H "Authorization: Bearer pjt_…" http://127.0.0.1:47614/api/v1/projects/MyGame/items?priority=high
claude mcp add --transport http projict http://127.0.0.1:47614/mcp --header "Authorization: Bearer pjt_…"
```

- **Same rules as agents:** your limits by priority apply, nothing can be deleted (except your own chat messages), and what's finished waits for your review. Results list what waits for the token under `waitingForYou`. Files are sent as uploads (JSON `{ "name", "data" }` in base64, or a multipart form) and come back as download links. A token can't read files on your computer that aren't attached in ProJict.
- **Network:** by default only this computer can connect. **Also let other devices on my network connect** serves HTTPS with ProJict's own certificate, made for this computer's name. Clients either trust it (**Save certificate…**) or check its fingerprint. Windows may ask whether ProJict may use the network: allow private networks only.
- **Internet:** ProJict opens nothing to the internet. To reach it from web-based connectors (claude.ai, cloud automations), run a tunnel such as [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) in front of it, and use a token limited to the projects it needs.
- **Protection:** web pages in a browser can't call the API, an address that sends 10 wrong tokens is locked out for 15 minutes, and a token may make up to 600 requests a minute.

### Tools

Outside tools your agents may use for your work: **Settings → Tools → Tools…** lists them, with ElevenLabs (voices, voice-over, sound effects and music, through its API), Suno (music, in the browser) and Tripo3D (3D models, in the browser) to start with. **Add a tool…** adds your own.

- **Each tool** says what it's for (agents read it to pick the right one), its website, and whether agents reach it **through its API, with a key** or **in the browser**. A browser tool says how you're signed in there; agents use the website with their own browser tools, and you sign in yourself. A **budget** ("$22 a month") is told to agents; ProJict doesn't count what's used.
- **API keys** are pasted into the key box and kept (with **Save key**, Enter, or when you pick another tool or close the window) protected for your Windows user, in tools.json next to ProJict's other settings on this computer: never in the workspace, its mirror or backups, and never shared. The window shows only the key's last characters.
- **Agents ask for a key** with `use_tool_key`. A bar at the bottom of ProJict says who wants which key and why: **Allow once**, **Always for** that agent, or **No**; the agent hears your answer. **Ask me again**, in the Tools window, takes back an "always". `list_tools` tells agents what each tool is for and how to reach it, never a key.
- **Per project:** tick the tools a project uses in its **Details → Tools** (or in the Tools window). Agents working in it are told them in `current_project`.
- **ComfyUI:** pick **ComfyUI (your own server)** for a tool, and agents run your ComfyUI workflows on it.
  - **Endpoints** are its servers by name and address (**This computer**, http://127.0.0.1:8188, to start with; add a PC on your network). **Check** says whether one answers, how many runs it has and its graphics card. An address pasted with ComfyUI's own path on the end (…/prompt) is cut back to the server's. Addresses are kept on this computer, like keys.
  - **Workflows** are added from files exported in ComfyUI with Workflow › Export (API) (ComfyUI's own save format is refused, with a word on how to export). They're kept in the data folder's `workflows` folder, a file each, so every computer with the workspace has them. Each says what it makes, for agents, and the inputs ProJict found in it: `prompt` (a text that feeds a sampler's positive, a Text node feeding a prompt, or a prompt typed into a node), `negative`, `seed`, `width`, `height`, `batch`, `image` (a LoadImage picture), and number nodes (Float, Int) by their title, e.g. `duration` for **Float (duration)**; a second one gets a number ("prompt 2").
  - **Agents** see the endpoints and workflows in `list_tools`. `run_workflow` fills in the inputs (`prompt=a red car at dusk`, `seed=random`, `image=sketch.png`), uploads any picture, queues it on the endpoint and waits in the background. What it made (what the workflow saves: pictures, video, sound or 3D models; its previews only when it saves nothing) is attached to the item the agent names, with a line in its history ("Ran the ComfyUI workflow “Text to image” on This computer: 1 file in 40s"), or kept in the data folder's `comfyui` folder when it names none. The agent hears when it's done or failed (with ComfyUI's reason), and `workflow_run` says how a run is going. `get_workflow` gives an agent the workflow itself, to call ComfyUI on its own.
  - **Agents may run its workflows**, ticked to start with: untick it and agents can still read the workflows, not run them. Attaching follows the same rules as attaching a file: the item must be one agents may work on.

### Shipping

Click **Ship** in a project's header (or right-click the project › **Ship…**) and tick what you want done: commit, build, package, push and/or release. An AI agent working in the project sees the request and posts its plan on the board: the version, what's in it, the items still waiting for your review and what it will run. **Approve** or **Decline** it there; nothing runs before you approve. The agent then runs the steps and reports each one under the plan, and the request shows in the sidebar, on the dashboard and in the Feed.

**Ship** and **Clean up** are the big buttons on the left of a project's header, with the others (Folder, VS Code, Terminal, GitHub, Chat, Wiki, Copy prompt, Release, Export) after them. The cog after those chooses which show big: tick any of them, or **As at first** for Ship and Clean up. It's the same for every project, on this computer.

How a project is shipped goes in its **Details → Shipping**: the steps it has and the instructions the agent follows (e.g. bump the version, run the build script, test, commit, push, publish the release). Push and release always need your approval; commit, build and package can run without asking if you tick that for the project.

Agents can write the steps and instructions too, for example after looking at how the project is built. Details → Shipping then says which agent changed them. Until you click **Looks good**, every ship request waits for your approval, so nothing an agent wrote runs unseen. Ctrl+Z doesn't undo shipping settings. Only you can let steps run without asking.

### Cleaning up

Click **Clean up** in a project's header (or right-click the project › **Clean up…**) to have an AI agent working in it look through its repo folder for what could go: old test builds, labs and installers, duplicate copies, build leftovers, logs and temp files. The agent posts a plan on the board, one line per file or folder with its size and why, as **safe** (build leftovers, temp files, duplicates whose copy stays) or **thorough** (also old builds, labs and doubtful things). Untick what should stay and click **Clean up safe** or **Clean up all ticked**, or **Decline**. ProJict itself moves exactly the ticked paths to the Recycle Bin and logs what that freed; agents never remove files.

A plan can't reach outside the repo folder or include the current test build, files with uncommitted changes are refused, and files git tracks are only proposed as thorough. While a clean-up is open, agents do no other work in the project, only read, comment and plan it; it shows with a broom in the sidebar. Ctrl+Z doesn't undo a clean-up, but the Recycle Bin does.

## Sharing

Other people on your network can work in your projects live, from their own ProJict.

- **Share yours:** open **Sharing** (the share button below the sidebar) and tick **Let other ProJict apps on your network connect**. Windows may ask once whether ProJict may use the network: allow it for private networks. Then **Create invite**: pick a role and, if you like, the groups they'll see. Give them the code and the address shown. A code works once, for 24 hours. Tick **Let them in without asking me** before creating it, and whoever uses the code is in at once, with that role and those groups (keep such a code to them).
- **Join someone's:** in **Sharing → Connect to another ProJict**, enter their address and code. The first time, compare the fingerprint ProJict shows you with the one in their Sharing window, then trust it. They get a bar to **Let in**, **Deny** or **Block** you (unless their code lets you in at once). Their projects then show in your sidebar under their name, and ProJict reconnects on its own after that.
- **You, on another computer:** when your own other computer asks to join, click **It's me** (or later **This is me…** in Sharing) and type the 6-digit code shown here on that computer. It then takes part as you: under your name in Chat (read marks shared), its changes signed with your name, and its agents counted as yours. Private projects stay here all the same. **Not me** makes it a guest again.
- **Private projects:** tick **Private** in a project's Details (under Sharing), or right-click it › **Private**, to keep it on your computer. People you share with, and their agents, then don't see it or its channels, even when its group is shared with them; it goes from their ProJict at once. You and your own agents still see it. Private projects show a lock in the sidebar.
- **Roles:** **Viewer** sees the projects and changes nothing. **Commenter** also takes part in discussions. **Reporter** also adds items, for testers or clients. **Editor** changes everything in the projects except their name, group, status and folder, and can't delete them. Change someone's role, block or remove them in the Sharing window at any time.
- **Live:** changes show on everyone's board as they're made, and a guest's change is an undo step on yours. When two people change different things at once, both changes are kept. Comments and history are signed with each person's name, whatever their ProJict claims, and a badge shows who has which project open.
- **Safety:** connections are encrypted. ProJict remembers each host's fingerprint and refuses to connect if it ever changes. Guests' copies are never saved on their computer, apart from pictures they open. For now sharing works on your local network only. Guests also take part in [Chat](#chat).
- **Guests' AI agents:** an agent connected to a guest's ProJict works in what you share with that guest, as far as the guest's role allows (a viewer's agent only reads) and only on items your agent rules allow (**Settings → AI agents**). Its work is signed with its name and the guest's, like "Ada (via Alice)", counts as agent work, and waits for your review. It also reads and posts in your channels the guest can see, and your @mentions of it reach it. Turn **Guests' AI agents may work in what you share with them** off in the Sharing window to let them only read; it's on by default. Both ProJicts need version 0.1.29 or later.

## Discussions

Items, categories and groups each have a discussion with threaded replies, for you and AI agents alike. Open one from an item's right-click menu (or its speech-bubble chip), the speech bubble in a category's header (a category's discussion also shows its items' comments, as sub-threads under each item), or by right-clicking a group heading in the sidebar › **Discussion**. It opens beside the board. Reply to any comment to start a sub-thread, and press Ctrl+Enter to post. Add files and pictures to a comment or a reply with the paperclip, by pasting a screenshot (Ctrl+V) or by dropping files on the box. Pictures show as thumbnails and open in ProJict's viewer, where a marked-up copy can go back as a reply. **Settings → Comments & history** sets the largest file allowed. Select any part of a comment to copy it (Ctrl+C or right-click › Copy), or copy a whole comment with the copy button that appears when you point at it. A red dot marks comments you haven't read yet, on the discussion's chip and on folded categories, folded Done lists, group headings and projects in the sidebar that hold some. Folded sections and projects also get one for an AI agent's work waiting for your review. Each item that waits for you has a red dot of its own, and pointing at a dot says what waits. **All states › Needs you** shows only those items; clicking a folded category's dot does the same. Opening the discussion clears its dot. Deleting a comment that has replies keeps the replies. On items and categories, Ctrl+Z on the board brings a deleted comment back.

When an agent gives you choices, they show under its comment as buttons, its suggestion first: click the one you want. With several questions, pick one answer each and press **Send answers** (or **Use all suggestions**). Your answer is posted as your reply, so the agent hears it, and the comment then shows what you chose.

## Chat

Live chat with your AI agents in #channels. Open **Chat** in the sidebar; its count shows unread messages in your channels, in red when one @mentions you. **@everyone** mentions everyone in the channel (not those who could only read it).

- **Channels:** start one with **+** in Chat, from the right-click menu of a project, category or item (**Start a chat channel…**), or with a project's **Chat** button. A channel about a project, category or item shows as a #chip there, and its name is suggested from it (for example #grid2vr-hud). A channel is **Open** (anyone who can see its project can read and join it) or **Invite only**. You're in every channel from the start; leave the ones you don't want from the channel's ⋯ menu. The channel list shows each channel's topic, and **Browse channels** (the list button in Chat) shows every channel with its topic, what it's about and its members, to open or join.
- **Messages:** Enter sends, Shift+Enter starts a new line, Up edits your last message. **@name** mentions someone (typing @ suggests the channel's members: Tab or Enter puts the name in), **#name** links a channel, and # with an item's id (#4e84570c) links the item; web links open in your browser. Add files and pictures like in discussions. **Reply** quotes the message you answer. Edit or delete your own messages. Select part of a message to copy it (Ctrl+C or right-click › **Copy**), or copy all of it with the copy button. A **New** line marks what came while you were away, and a channel opens there. A channel shows its newest 30 messages at first; older ones come as you scroll up. **Ctrl+K** search finds messages too, and the Feed shows channels being started.
- **Private messages:** right-click someone (a member in Chat, a message's author, or an agent's card in the Agents view) › **Private message** for a conversation just between the two of you. They list under **Private messages**, below all channels, and count as for you (red), like an @mention. Agents write privately with `post_message` to `@name`, also to each other.
- **A channel's project:** a channel about a project has a button with the project's name by its own: a click opens the project's board. A channel not linked yet but named after a project (#dirt2vr for DIRT2VR) offers **Link to DIRT2VR**, and moderators link or unlink any channel from its ⋯ menu › **About a project**; linked, it opens from the project's **Chat** button and chip too.
- **Searching:** the box at the top of Chat's list (Ctrl+F) finds the messages with all your words, in the text, who wrote it or the channel's name, newest first, in your channels, your private conversations (and the agents', while they show) and other ProJicts' shared with you. They show instead of the channels: a click opens the channel at the message, and the results stay for the next one. The **#** button beside the box keeps it to the open channel or conversation (the box then says "Search #general"), and stays on until you turn it off; Esc (or ×) brings the channels back.
- **Archive:** right-click one of your private conversations › **Archive** to move it to **Archive** at the bottom of the list (folded until you open it). Nothing new in it counts or notifies you, @mentions included, until you open it or right-click › **Take out of the archive**, which brings it back and opens it. It's archived only for you.
- **Folding the list:** click a heading in Chat's list (**Channels**, **Other channels**, **Private messages**, or another ProJict's) to fold it away; click it again to unfold it. A folded heading still shows the channel you have open and any with something new, says how many more it hides, and stays folded until you unfold it.
- **Agents' private chats:** the toggle in Chat's header opens a panel with what your agents write to each other privately. You read them but don't write in them. Right-click one to **Suspend** it (neither agent can write in it until you **Resume** it), delete it, or write to either agent.
- **Who's here:** a dot on each member's badge says whether they're online (green), away (amber: nothing done on their computer for 10 minutes, or, for an agent, no ProJict tool used for 10 minutes) or offline (grey: their ProJict or the agent isn't connected). Away and offline also show under their name. People you share with and their agents show as their ProJict says, and in their ProJict your channels' members show as yours says.
- **Your other ProJicts' channels:** a ProJict linked as you ("It's me", such as your laptop) shares all its own channels back with yours; they show under "iztok4090's ProJict", and you read and write in them as you. Someone else's ProJict shares its Open channels (not a private project's) when they tick **Share my Open channels with …** in Sharing, and you write there as a visitor. Each channel from another ProJict is tagged with whose it is ("#hud · iztok4090"), also in Ctrl+K search and notifications.
- **Agents in other ProJicts:** the ProJicts you share with tell yours which agents they have connected (and yours tells them), so a channel's invite list offers them while they're connected, as "Hermes (via alice)", before they've done anything here.
- **Moderation:** whoever starts a channel moderates it, and you moderate every channel, including ones an agent started. Moderators invite (agents connected now come first in the list), mute (for 15 minutes, an hour or until unmuted; muted members can still read), remove members (they can't rejoin until invited again), make others moderators, change the topic, open a channel or make it invite only, and delete messages. Only you delete channels; a deleted channel's file is kept in backups\deleted.
- **AI agents** read, post, start channels, invite and moderate with their own tools, and `wait_for_messages` lets an agent listen (an invitation or @mention wakes it). When something waits for an agent (an invitation, an @mention, new messages in its channels), the result of its next tool call says so and asks it to reply. An @mention of an agent that isn't connected waits for it for a week. ProJict asks agents to keep Chat human: short, conversational messages, one point at a time, with details in the item's discussion or a note, and long or technical exchanges between agents in private conversations. A wall of text in a channel is still posted, but the agent gets a reminder back. Each agent can post at most 20 messages a minute. Turn Chat off for agents under **Settings → AI agents**.
- **Notifications:** an @mention of you notifies (on by default); every message in your channels can too (**Settings → Notifications**).
- **People you share with** (see [Sharing](#sharing)) take part from their own ProJict. They see the Open channels about the projects you share with them, and the channels you invite them to (they're in the invite list, marked guest); channels about nothing in particular only when invited. Viewers read; commenters and reporters also write, add files and send private messages to you or your agents; editors can also start channels about the projects shared with them. You and a channel's moderators mute or remove them like anyone else. In their Chat your channels show under your name, live, with unread counts and notifications. Everything stays with you; their ProJict keeps nothing apart from pictures they open. Their AI agents read and post there too, as "Ada (via Alice)" (see [Sharing](#sharing)).

## Wiki

One wiki for the whole workspace, for what's worth keeping: how things work, decisions, guides. Open **Wiki** in the sidebar (under Chat); its count shows pages AI agents changed that you haven't checked yet.

- **Pages** sit in folders, like GRID2VR › Architecture › Renderer. **+** (Ctrl+N) starts a page next to the open one. Rename a page in its title, or move it with ⋯ › **Move or rename…** (folders and name separated by /). The box above the tree finds pages by name or text, and **Ctrl+K** finds them too. Drag the list's edge to make it wider or narrower, and the line between the editor and its preview to share the room differently; both stay as you leave them.
- **Writing:** **Edit** (or a double-click on the page) opens its Markdown with a live preview beside it: headings (`#`), **bold** and *italics*, lists and `- [ ]` tasks, tables, code blocks, quotes and rules. Paste or drop pictures and files into the editor: they're attached to the page and shown (`![](picture.png)`; a video or sound plays there) or linked where you're writing; **Attach files…** below the page does the same. Right-click a picture or player in the preview to size it (small, medium, large, full width), place it left, centre or right, let text flow beside it, or caption it; it's written after it in braces, e.g. `![](picture.png "A caption"){medium center}`, `{320px}`, `{40% right wrap}`. **Ctrl+S** saves. Going to another page or view saves too; **Cancel** throws your changes away.
- **Links:** `[[Page name]]` (or `[[GRID2VR/HUD|the HUD]]`) links a page, by its whole path, a page in the same folder or its name. A link to a page that isn't written yet shows in orange: click it to start that page. # and an item's id (#4e84570c) links the item, #name a chat channel, and web links open in your browser. **Linked from**, under a page, lists the pages that link to it; ⋯ › **Copy link to this page** copies its `[[…]]`.
- **Projects:** pick the project a page is about, under its title. It then shows as a chip on the project's header, next to its channels, and is shared as the project is. The header's **Wiki** button opens the project's first page, or starts one. In a project's **Notes**, **To wiki** turns the note into a page about the project, with its files.
- **History:** every save is a version, with who saved it and when. **History** lists them with what each changed, compares one with the page as it is now, and **Restore this version** makes it the newest again (nothing is lost). It stays on as you open other pages, each showing its own versions, until you turn it off or start editing.
- **Editing at the same time:** if someone saves a page while you're editing it, the editor says so, and your save merges with theirs paragraph by paragraph. If you both changed the same paragraph, both versions are kept: the page shows the earlier save, and a red bar offers **Compare**, **Use theirs**, **Keep the page as it is** or **Merge by hand**.
- **AI agents** use `list_wiki`, `read_wiki` and `write_wiki` (a whole page, or one section by its heading). They pass the version they read, so their changes merge with yours the same way. A page an agent changed gets a yellow bar: **What changed** shows the diff since you last checked, **Looks good** clears it. Saving the page yourself counts as having checked it. An API token limited to some projects reaches only the pages about those projects.
- **The studio's lead reviews for you** (when you let it): in a project's **Details → Studio**, tick **The lead designer reviews wiki pages** (the director, in a film studio), and optionally name one folder. Pages about the project that the studio's other agents change then wait for the lead: it's told about each, reads what changed and accepts it with `review_wiki`, or sends it back with a note that goes privately to whoever changed it (the page keeps waiting until it's changed again). Your yellow bar says the lead reviews it, or that it was sent back and why. An accepted page leaves your review list and the sidebar's count; a grey bar says who accepted it, **What changed** shows what they accepted, and **Send back** puts it back in review, for the lead or you. History marks each acceptance and sending back. The lead's own changes, changes by agents not hired in the studio, clashing edits and pages outside the project or folder still wait for you.
- **Sharing** (see [Sharing](#sharing)): a page about a project goes to the people you share that project with, never a private project's. A page without a project stays on your computer unless you tick **Share with everyone I share with**. In their ProJict your pages show under "<your name>'s wiki". Editors change them, as versions signed with their names and merged like yours; others read them. Their agents read what their person can, and write only when that person is an editor and you let guests' agents work: signed "Ada (via Alice)", waiting for your review. Linking, sharing, checking and deleting pages stay yours.
- **Diagrams:** write one as text in a ` ```mermaid ` block and the page shows it drawn: flowcharts, sequence, class, state and ER diagrams, Gantt charts and the rest of [Mermaid](https://mermaid.js.org)'s kinds, in ProJict's light or dark look and in the live preview as you type. **Diagram** in the editor puts a starter of each kind where you're writing, to change from there. A diagram wider than the page is shown smaller; click one to open its picture. A diagram that doesn't draw says why above its text, and agents hear it from `read_wiki`. They're drawn by Microsoft Edge WebView2, which comes with Windows 11 (on Windows 10, install it from Microsoft), and kept as pictures, so pages open at once after the first time. A `drawio` block shows as its code for now.

## More

- **Finding projects**: type in **Filter projects** above the sidebar list or on the dashboard to narrow it down. The eye button next to it shows or hides individual projects or whole groups. Hidden projects are hidden in both the sidebar and the dashboard. Click a group heading (Personal, Work, …) to collapse it. You can also right-click a project to hide it.
- **Groups**: Personal and Work are always there. Add your own with the folder button under the sidebar, then right-click a project › **Move to group**. Right-click a group heading to rename or delete it (its projects move back to Personal).
- **GitHub issues**: with a project's GitHub URL set, **Details → GitHub issues → Import issues** brings the repository's open issues in as items of a GITHUB category. Each shows its issue number, and pull requests that mention it ("Fixes #12") show next to it; click one to open it on GitHub. **Sync now** (and, if you leave it on, every start of ProJict) brings in new issues and closes or reopens items whose issues were closed or reopened on GitHub. Tick **Close an issue on GitHub when I finish its item here** to also go the other way; that needs the GitHub CLI sign-in (**Settings → GitHub**) with access to the repository. Private repositories need that sign-in too.
- **Releases on GitHub**: enter your GitHub account under **Settings → GitHub** (tick the GitHub CLI option to include private repositories). ProJict links projects to repositories with the same name, shows each one's latest release on its dashboard card, and the dashboard's **Released** filter lists them. A project's own GitHub link (Details) always wins.
- **Reusing a project's layout**: right-click a project and choose **Copy categories from** to add another project's categories (without its items).
- **Time**: each project's **Time** tab adds up how long was spent on it, in all and this week, week by week (people and agents), per person and agent (items done, time, and the tokens and cost agents reported), and the items that took longest. Time counts while an item is in progress, for whoever put it there (an agent's check-out too); add more by hand with right-click › **Log time…** (1h 30m, 45m, 2:15). Agents report tokens and cost with `complete_item` or `log_work`. An item shows its time as a small chip, and the dashboard's **Table** has **Time** and **Tokens** columns.
- **Dashboard**: progress, open bugs and stale projects across all projects, plus everything finished in the last week. The switch at its top right shows projects as **Cards**, a **List** (a line each), a **Table** (click a heading to sort by it) or a **Board** with a column per status, where dragging a project to another column changes its status. List and Table group projects like the sidebar (**In groups**), and **Panels** folds away the panels on the right. ProJict remembers the choice on this computer.
- **Notifications**: Windows notifications for what needs you, while ProJict isn't in front: work to review, new comments in your discussions, ship plans to approve and people asking to join. You can also turn on agents checking out items, every comment, expiring API tokens and updates. Choose under **Settings → Notifications**; mute a project from its right-click menu. A click opens ProJict at the thing.
- **Feed**: everything that happened across your projects, newest first: items added and finished, what AI agents did, comments, releases and notes. Filter by project, kind, person or agent and period, or search. Click an entry to go to it; a comment opens its discussion beside the Feed.
  - **Group by** day, week, month or year (by year, the Feed goes back all the way). Click a period's name to fold it; **Collapse all** folds them all, for an overview.
  - **Stats** next to a period opens its numbers and charts: how much happened, by people and by AI agents, when (by hour, by day, or by month for a year), what kind of thing, in which projects and by whom. Hover a bar for its numbers.
- **Inbox and quick capture**: press **Ctrl+Alt+J** anywhere (changeable in Settings) to jot down an item or idea. Turn an idea into a project from its right-click menu.
- **Attachments**: drag files onto an item, paste a screenshot or copied files with Ctrl+V while editing it, or right-click it › **Attach files…**. To start a new item with a screenshot, paste it into the **Add item** box. Images show as thumbnails under the item. Click a picture to open it in ProJict's viewer, where you can mark it up (pen, highlighter, arrows, boxes, circles) and **Save copy** next to the original. Other files open in their usual app. Right-click an attachment to show it in its folder, copy its path or remove it.
- **Audio and video play in place**: in Chat, discussions, items, notes, linked media and wiki pages, an audio or video file has its own player: play/pause (or click the picture), a seek bar with the time, volume and mute, and a button to open it in its own app. A video shows a frame from it until it plays. One plays at a time, nothing is loaded until you press play, and leaving the view lets go of the file. A file Windows can't play says so and keeps the button to open it.
- **Copy prompt**: copies selected items as a ready-made prompt for AI coding assistants. The prompt includes the project's folder, GitHub link, your own standing instructions (set in **Details**) and the paths of attached files.
- **Project links**: open the project's folder, VS Code, a terminal or its GitHub page from the project header.
- **Releases**: turns everything finished since the last release into patch notes you can copy or save.
- **Notes**: free-text notes per project, with attached files. **To wiki** turns one into a [wiki](#wiki) page.

## Your data

Projects are saved as JSON files in the folder you chose, chat channels in its `chat` folder and wiki pages in its `wiki` folder (each with all its versions), with automatic backups in its `backups` folder. Pictures of wiki diagrams are kept in `%LocalAppData%\ProJict\diagrams`, and drawn again when missing. Attached files are copied into its `attachments` folder, so the originals can be moved or deleted. A file removed from an item is deleted once no backup refers to it any more. Uninstalling ProJict leaves your data where it is.
